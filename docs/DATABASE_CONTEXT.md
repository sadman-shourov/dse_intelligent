# DSE Intelligence — Database Context for Claude

This is the complete reference for the DSE (Dhaka Stock Exchange) PostgreSQL
database. Read this before answering any data question. It tells you what each
table means, the grain of each table, how they join, and which table to query
for which kind of question. Examples are written against the **real live schema**
(verified by introspection), including known drift from the idealised schema.

---

## 1. Mental model

The database has three layers. Almost every question maps to one of them.

1. **Market data** — prices, volumes, the index. The factual record of what
   traded. Tables: `stocks_master`, `price_history`, `index_ohlc`, `index_ticks`,
   `market_summary`, `live_ticks`, `live_ticks_archive`, `stock_fundamentals`.
2. **Analysis & signals** — computed indicators (RSI, MACD, moving averages,
   support/resistance), classifications, and BUY/WATCH/EXIT calls plus their
   measured outcomes. Tables: `analysis_results`, `signals`, `signal_outcomes`,
   `accuracy_scores`, `extreme_move_alerts`.
3. **Traders & portfolio** — the humans, their holdings, trades, watchlists, and
   the Telegram pulse log. Tables: `traders`, `portfolio_holdings`,
   `trade_transactions`, `trader_watchlist`, `trader_preferences`,
   `trader_stock_intents`, `trader_performance`, `positions`, `pulse_log`.

**Two hub keys join everything:**
- `stocks_master.symbol` — every stock-related table has a `symbol` FK to it.
- `traders.id` — every trader-related table has a `trader_id` FK to it.

## 2. Conventions you must know

- **Symbol** = the DSE trading code (e.g. `GP`, `BEXIMCO`, `SQURPHARMA`).
  Uppercase. It is the only stock identifier. **There is no company-name or
  sector column anywhere in this database.** If a user asks by company name or
  by sector, you cannot resolve it from the DB. Say so.
- **Dates** are stored as `date` (no time) for daily series. Timezone for the
  market is **Asia/Dhaka (UTC+6)**. Trading days are **Sunday–Thursday**.
  Market hours ~10:00–14:30 Dhaka.
- **`session_no`** appears in intraday/analysis tables. It is the intraday poll
  number within a trading day (1 = first poll, rising through the session).
  `session_no = 0` or NULL generally means an end-of-day / non-session run.
- **Numeric units**: prices are BDT. `value`/`total_value_mn`/`*_mn` columns are
  in **millions of BDT**. `volume` is share count. `total_market_cap_mn` is
  market cap in millions BDT.
- **`ltp`** = last traded price. **`ycp`** = yesterday's close price (the prior
  session's close, used to compute change %). **`close`** = official daily close.
  For end-of-day rows `ltp` usually equals `close`; for charting use `close`.
- **Freshness differs by table** (see each table's date range). Price history is
  deep; analysis only exists from April 2026 onward.

## 3. Table-by-table reference

Row counts and date ranges below are accurate as of this writing; use them to
judge coverage, not as hard limits.

### 3A. Market data

#### `stocks_master` — the symbol registry (397 rows)
The list of all DSE instruments. The hub every stock table joins to.
- `symbol` (PK), `is_dsex` (bool; TRUE for 320 DSEX constituents, FALSE for 77),
  `is_active` (bool; filter `is_active = TRUE` for the tradable universe),
  `created_at`, `updated_at`.
- **No name, no sector.** This is the single biggest limitation. Flag it.

#### `price_history` — daily OHLCV per stock (206,685 rows; 2024-04-08 → 2026-06-30)
The core table for stock charts and any historical price math.
- Grain: one row per `(symbol, date)`. UNIQUE(symbol, date).
- Columns: `open, high, low, close, ltp, ycp, trade, value, volume`.
- `trade` = number of trades. `value` = turnover in millions BDT.
- Use `close` for candlesticks and returns. Use `ycp` for day change %.
- FK: `symbol → stocks_master.symbol`.

#### `index_ohlc` — daily index candlesticks (11,233 rows; 2003-01-01 → 2026-06-30)
OHLC candles for the market indices. DSE does not publish these; we built them.
- Grain: one row per `(index_code, date)`. UNIQUE(index_code, date).
- `index_code` ∈ {`DSEX` (5,687 rows, back to 2003), `DS30` (2,773, to 2014),
  `DSES` (2,773, to 2014)}.
- `open, high, low, close, volume`, plus `source` ∈ {`stocknow` (history),
  `self` (generated by our own EOD rollup going forward)}.
- **Caveat**: for `source='stocknow'` rows, `open` is the prior day's close
  carried forward, not a true session open. `high/low/close` are real. `volume`
  is total market volume, not an index share count.
- This is the table for **index candlestick charts**.

#### `index_ticks` — intraday index samples (small, rolling)
Raw intraday samples of the live index value, appended each time
`fetch_market_summary` runs during market hours. The EOD rollup turns each day's
rows into one `index_ohlc` candle. Not for analysis directly; it is the feedstock
for `index_ohlc` (`source='self'`).
- Columns: `date, fetched_at, dsex, ds30, dses`.

#### `market_summary` — daily market totals + index close (261 rows; 2025-01-06 → 2026-06-30)
One row per trading day with whole-market aggregates and the index closing values.
- **Grain & key**: `trade_date` is the PRIMARY KEY (note: column is `trade_date`,
  not `date`).
- Columns: `total_trade` (bigint), `total_volume` (bigint),
  `total_value_mn` (double), `total_market_cap_mn` (double),
  `dsex_index`, `dses_index`, `ds30_index`, `dgen_index` (all double).
- The index values here are **close-only** (one number per day). For OHLC use
  `index_ohlc`. `dgen_index` is often 0 (legacy index, mostly unused).

#### `live_ticks` — today's intraday stock ticks (current day only, 385 rows)
Intraday per-stock snapshots for the current trading day. Cleared/archived nightly.
- Grain: `(symbol, date, session_no)`. UNIQUE on those three.
- Columns: `fetched_at, ltp, high, low, close, ycp, change_val, trade, value, volume`.
- Use for "live" / intraday questions about today. For history use the archive.

#### `live_ticks_archive` — historical intraday stock ticks (143,597 rows; 46 days)
Same shape as `live_ticks` but the long-term store (`archived_at` instead of
`created_at`). No FK enforced. Query here for past intraday detail.

#### `stock_fundamentals` — P/E and EPS per stock (9,504 rows; 2026-04-08 → 2026-06-29)
- Grain: `(symbol, fetched_at)`. UNIQUE on those. `fetched_at` is a `date`.
- Columns: `pe_ratio`, `eps`. Take the latest `fetched_at` per symbol for current.
- FK: `symbol → stocks_master.symbol`.

### 3B. Analysis & signals

#### `analysis_results` — full computed analysis per stock (20,884 rows; 2026-04-14 → 2026-06-30)
The richest analytical table. This is where the stocknow-style indicators live
(RSI, MACD, moving averages, support/resistance, fibonacci, volume profile).
- Grain: `(symbol, analysis_date, session_no)`. UNIQUE on those three. There can
  be **multiple rows per symbol per day** (one per session). To get the latest,
  use DISTINCT ON (see §6).
- Flat columns: `rsi`, `confidence_score`, `overall_signal`, `stock_class`,
  `breakout_signal`, `volume_signal`.
- JSONB columns: `support_levels`, `resistance_levels`, `fib_levels`, `macd`,
  and the big one, **`raw_output`** (full field map in §5).
- Categorical values:
  - `overall_signal` ∈ {WATCH, HOLD, EXIT, BUY}
  - `stock_class` ∈ {TRADING, INVESTMENT, GAMBLING}
  - `volume_signal` ∈ {normal, high, low}
  - `breakout_signal` is currently always `NONE`.
- FK: `symbol → stocks_master.symbol`.

#### `signals` — flat signal feed (18,876 rows; 2026-04-14 → 2026-06-30)
A denormalised, one-row-per-signal table (lighter than `analysis_results`).
- Columns: `signal_type` ∈ {WATCH (14,421), EXIT (3,375), BUY (1,080)},
  `signal_date`, `price_at_signal`, `reason`, `is_active`.
- Note: there can be multiple signal_types per symbol per day. Filter
  `is_active = TRUE` for current signals.
- FK: `symbol → stocks_master.symbol`.

#### `signal_outcomes` — backtested signal results (20,811 rows; 2026-04-08 → 2026-06-29)
How past signals actually performed. Use for accuracy / win-rate questions.
- Grain: `(symbol, signal_date, signal_type)`. UNIQUE on those.
- Columns: `price_at_signal`, `eval_date`, `price_at_eval`, `pnl_pct`,
  `outcome` ∈ {NEUTRAL (12,344), WIN (5,205), LOSS (3,262)}, `days_held`,
  `signal_reason`.
- FK: `symbol → stocks_master.symbol`.

#### `accuracy_scores` — aggregated accuracy by period (56 rows)
Rolled-up win rates per `signal_type` over a date window.
- Grain: `(period_start, period_end, signal_type)`. `signal_type` can be NULL
  (= all signals combined).
- Columns: `total_signals, wins, losses, neutrals, win_rate, avg_pnl_pct,
  best_signal, worst_signal`.

#### `extreme_move_alerts` — big intraday movers (804 rows; 2026-04-14 → 2026-06-30)
Stocks that moved beyond a threshold intraday.
- Grain: `(symbol, alert_date)`. UNIQUE.
- Columns: `change_pct`, `direction` ∈ {up (688), down (116)}, `price`,
  `session_no`.

### 3C. Traders & portfolio

#### `traders` — the users (6 rows)
- `id` (PK), `name`, `telegram_chat_id`, `is_active`, `onboarding_complete`,
  `trading_style`, `risk_tolerance`, `holding_period`, `strategy_notes`,
  `preferences` (JSONB, e.g. `{"risk_pct": 2.0, "portfolio_size": 500000}`).

#### `portfolio_holdings` — current open positions per trader (37 rows)
- Grain: `(trader_id, symbol)`. UNIQUE. Filter `is_open = TRUE`.
- Columns: `quantity, avg_buy_price, total_invested, first_bought_at,
  last_updated, target_price, position_size_bdtt`.
- FKs: `trader_id → traders.id`, `symbol → stocks_master.symbol`.
- For P&L, join to the latest `price_history.close` (see §7).

#### `trade_transactions` — buy/sell ledger (10 rows)
- Columns: `transaction_type` ∈ {BUY, SELL}, `quantity, price, total_value,
  transaction_date, brokerage_fee`.
- FKs: `trader_id → traders.id`, `symbol → stocks_master.symbol`.

#### `trader_watchlist` — watched symbols (1 row)
- Grain: `(trader_id, symbol)`. UNIQUE. `target_price`, `is_active`.

#### `trader_preferences` — structured prefs (2 rows)
- `trader_id` (PK), `trading_style, holding_period, risk_tolerance,
  preferred_signals, avoid_signals`.

#### `pulse_log` — Telegram pulse history (3,726 rows)
- `pulse_date, session_no, deepseek_input` (JSONB), `deepseek_output` (text),
  `telegram_sent`, `sent_at`, `trader_id`.

#### Empty / unused tables (exist but currently 0 rows)
- `positions` (0) — legacy/global positions; superseded by `portfolio_holdings`.
- `trader_performance` (0) — intended daily P&L snapshots, not yet populated.
- `trader_stock_intents` (0) — intended per-stock intents, not yet populated.

Do not rely on these for answers; note they are empty if asked.

## 4. Relationship / join map

```
stocks_master (symbol) ──┬─< price_history.symbol
                         ├─< index_ohlc            (NO fk; join on nothing — index_code, not symbol)
                         ├─< live_ticks.symbol / live_ticks_archive.symbol
                         ├─< stock_fundamentals.symbol
                         ├─< analysis_results.symbol
                         ├─< signals.symbol
                         ├─< signal_outcomes.symbol
                         ├─< extreme_move_alerts.symbol  (NO fk, but symbol matches)
                         ├─< portfolio_holdings.symbol
                         ├─< trade_transactions.symbol
                         └─< trader_watchlist.symbol

traders (id) ──┬─< portfolio_holdings.trader_id
               ├─< trade_transactions.trader_id
               ├─< trader_watchlist.trader_id
               ├─< trader_preferences.trader_id
               ├─< trader_stock_intents.trader_id
               ├─< trader_performance.trader_id
               └─< pulse_log.trader_id

market_summary (trade_date)  — standalone daily; join to price_history/index_ohlc on date
index_ohlc (index_code, date) — standalone; index_code is a label, not a stock symbol
```

## 5. `analysis_results.raw_output` field map (JSONB)

This single column holds nearly every indicator a stocknow-style chart shows.
Present in ~20,496 rows. Top-level keys and what they contain:

| Key | Type | Contents |
|-----|------|----------|
| `current_price` / `current_ltp` | number | price the analysis was run on |
| `rsi` | object | `{rsi, signal, oversold, overbought, rsi_direction, averaging_zone}` |
| `macd` | object | `{signal, histogram, macd_line, signal_line}` (signal e.g. `bullish_crossover`) |
| `moving_averages` | object | `{ma20, ma50, ma200, trend, above_ma20/50/200, price_vs_ma20/50/200_pct}` |
| `sr` | object | `{support:[...], resistance:[...], current_price}` support/resistance |
| `fib` | object | `{levels:{0,23.6,38.2,50,61.8,78.6,100}, low_90d, high_90d, current_zone}` |
| `volume` / `volume_profile` | object | `{signal, pct_vs_avg, avg_volume_20d, current_volume, volume_price_pattern}` |
| `breakout` | object | `{breakout, breakout_level, volume_confirmed, avg_volume_20d}` |
| `market_trend` | object | `{trend, dsex_5d_change_pct, consecutive_up_days, consecutive_down_days}` |
| `market_context` | object | `{dsex_index, dses_index, trade_date, total_trade, total_volume, total_value_mn, dsex_change_pct}` |
| `score_breakdown` | object | point contributions that sum to the confidence score (`total`) |
| `class_flags` | object | `{is_dsex, mutual_fund, new_listing, suspected_z_category}` |
| `trade_setup` | object | `{has_setup, ...}` entry/stop/target when a setup exists |
| `signal_reason` | string | human-readable reason, e.g. "MACD bullish crossover + High volume" |
| `pe_ratio`, `eps` | number | fundamentals snapshot at analysis time |
| `intraday_momentum`, `relative_strength` | object | often `available:false` early in data |
| `confirming_signals` | number | count of confirming indicators |

Query JSONB with `->` (object) and `->>` (text), e.g.
`raw_output->'rsi'->>'rsi'`, `raw_output->'moving_averages'->>'ma50'`.

## 6. Critical query patterns (must-knows)

**Latest analysis per symbol** (multiple sessions exist per day):
```sql
SELECT DISTINCT ON (symbol) symbol, overall_signal, confidence_score, rsi, raw_output
FROM analysis_results
WHERE analysis_date = (SELECT MAX(analysis_date) FROM analysis_results)
ORDER BY symbol, analysis_date DESC, session_no DESC NULLS LAST, id DESC;
```

**Latest daily price per symbol:**
```sql
SELECT DISTINCT ON (symbol) symbol, date, close, ycp, volume
FROM price_history
ORDER BY symbol, date DESC;
```

**Always**: filter `is_active = TRUE` on `stocks_master` for the tradable
universe; filter `is_active = TRUE` on `signals` for current signals; filter
`is_open = TRUE` on `portfolio_holdings`.

## 7. Question → table routing (the playbook)

For each common ask, the table(s) to hit and a ready recipe.

**Stock candlestick / price chart** → `price_history`
```sql
SELECT date, open, high, low, close, volume
FROM price_history WHERE symbol = 'GP' AND date >= '2026-01-01'
ORDER BY date;
```

**Index candlestick (DSEX/DS30/DSES)** → `index_ohlc`
```sql
SELECT date, open, high, low, close, volume
FROM index_ohlc WHERE index_code = 'DSEX' AND date >= '2024-01-01'
ORDER BY date;
```

**Latest quote / current price of a stock** → `price_history` (or `live_ticks`
for intraday today)
```sql
SELECT date, close, ycp, ROUND((close-ycp)/NULLIF(ycp,0)*100, 2) AS change_pct
FROM price_history WHERE symbol = 'GP' ORDER BY date DESC LIMIT 1;
```

**RSI / MACD / moving averages / support-resistance for a stock** →
`analysis_results.raw_output` (use the latest-per-symbol pattern in §6)
```sql
SELECT analysis_date,
       raw_output->'rsi'->>'rsi'              AS rsi,
       raw_output->'macd'->>'signal'          AS macd_signal,
       raw_output->'moving_averages'->>'ma50' AS ma50,
       raw_output->'sr'->'support'            AS support,
       raw_output->'sr'->'resistance'         AS resistance
FROM analysis_results WHERE symbol = 'GP'
ORDER BY analysis_date DESC, session_no DESC NULLS LAST LIMIT 1;
```

**Today's BUY / WATCH / EXIT signals** → `signals` (light) or `analysis_results`
(with detail)
```sql
SELECT signal_type, symbol, price_at_signal, reason
FROM signals
WHERE signal_date = (SELECT MAX(signal_date) FROM signals) AND is_active = TRUE
ORDER BY signal_type, symbol;
```

**Top gainers / losers for a day** → `price_history`
```sql
SELECT symbol, ROUND((close-ycp)/NULLIF(ycp,0)*100, 2) AS change_pct, close, volume
FROM price_history
WHERE date = (SELECT MAX(date) FROM price_history) AND ycp > 0
ORDER BY change_pct DESC LIMIT 10;            -- ASC for losers
```

**Biggest intraday movers / alerts** → `extreme_move_alerts`
```sql
SELECT symbol, change_pct, direction, price
FROM extreme_move_alerts WHERE alert_date = CURRENT_DATE
ORDER BY ABS(change_pct) DESC;
```

**Fundamentals (P/E, EPS)** → `stock_fundamentals` (latest per symbol)
```sql
SELECT DISTINCT ON (symbol) symbol, pe_ratio, eps, fetched_at
FROM stock_fundamentals ORDER BY symbol, fetched_at DESC;
```

**Market overview for a day** → `market_summary` (+ `index_ohlc` for the candle)
```sql
SELECT trade_date, dsex_index, ds30_index, dses_index,
       total_volume, total_value_mn, total_market_cap_mn
FROM market_summary ORDER BY trade_date DESC LIMIT 1;
```

**Signal accuracy / win rate** → `signal_outcomes` (raw) or `accuracy_scores`
(rolled up)
```sql
SELECT signal_type,
       COUNT(*) FILTER (WHERE outcome='WIN')  AS wins,
       COUNT(*) FILTER (WHERE outcome='LOSS') AS losses,
       ROUND(AVG(pnl_pct), 2)                 AS avg_pnl_pct
FROM signal_outcomes
WHERE signal_date >= CURRENT_DATE - INTERVAL '30 days'
GROUP BY signal_type;
```

**A trader's portfolio with P&L** → `portfolio_holdings` + latest `price_history`
```sql
SELECT h.symbol, h.quantity, h.avg_buy_price, p.close AS current_price,
       ROUND((p.close - h.avg_buy_price) * h.quantity, 2) AS pnl_value,
       ROUND((p.close - h.avg_buy_price)/h.avg_buy_price*100, 2) AS pnl_pct
FROM portfolio_holdings h
LEFT JOIN LATERAL (
    SELECT close FROM price_history ph
    WHERE ph.symbol = h.symbol ORDER BY date DESC LIMIT 1
) p ON TRUE
WHERE h.trader_id = 7 AND h.is_open = TRUE;
```

**Moving average / returns / volatility over time** → `price_history` with window
functions on `close`.

## 8. Known limitations — state these when relevant

- **No company names, no sectors.** Only trading codes. Sector analysis,
  "show me banks", or name lookups are not possible from the DB as-is.
- **No news / announcements** stored.
- **Analysis depth is shallow**: `analysis_results`, `signals`, `extreme_move_alerts`
  only start ~April 2026. Price history goes back to 2024; index OHLC to 2003.
  Do not promise indicator history older than the analysis window.
- **Intraday stock data**: only the current day in `live_ticks`; older intraday
  is in `live_ticks_archive` (46 days). Not a deep intraday store.
- **`breakout_signal` column is always `NONE`** — read breakout state from
  `raw_output->'breakout'` instead.
- **`market_summary` index values are close-only.** Use `index_ohlc` for OHLC.
- **Empty tables**: `positions`, `trader_performance`, `trader_stock_intents`.
- **`index_ohlc` open** (stocknow source) is carried-forward, not a true open.

## 9. Safety notes for query execution

- This is a **production** database. Prefer read-only `SELECT`. Never write
  (INSERT/UPDATE/DELETE) unless explicitly instructed.
- Always bound large tables (`price_history`, `analysis_results`,
  `live_ticks_archive`, `signal_outcomes`) by `symbol` and/or a date range.
  Avoid unfiltered full scans.
- When "latest" is requested and a table has multiple rows per symbol per day
  (`analysis_results`), use the DISTINCT ON pattern in §6, not `LIMIT 1` alone.
- Index values use `index_code`, not a stock `symbol`. Do not join `index_ohlc`
  to `stocks_master`.
